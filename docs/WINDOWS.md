# cue на Windows

Эта инструкция относится к Windows 10 версии 2004 и новее, а также к Windows 11. В более старых версиях Windows защита окна от захвата работает иначе: вместо полного исключения cue из записи может появиться чёрный прямоугольник.

## Требования

- Windows 10 2004+ или Windows 11.
- Node.js 18 или новее с npm. Для обычной разработки рекомендуется актуальная LTS-версия Node.js.
- Подключение к интернету: при установке загружаются зависимости, а во время работы cue обращается к выбранному AI-провайдеру.
- API-ключ OpenAI, Anthropic, Google Gemini, NVIDIA или совместимого gateway. Для локального Custom endpoint без аутентификации ключ не нужен.
- Для функций прослушивания нужен ключ с поддержкой распознавания речи: OpenAI с доступом к Whisper/audio API или Google Gemini.
- Рабочий микрофон и разрешение Windows на доступ настольных приложений к нему.

Нативных модулей в проекте нет, поэтому Visual Studio Build Tools для обычной установки не требуются.

## Запуск из исходников

Откройте PowerShell в каталоге проекта и выполните:

```powershell
npm ci
npm start
```

`npm ci` устанавливает версии из `package-lock.json` и перед установкой пересоздаёт `node_modules`. При первом запуске Electron и остальные зависимости могут загружаться несколько минут.

После `npm start` появится прозрачное окно cue поверх остальных окон и значок cue в системном трее. Окно не отображается на панели задач. Через меню значка можно показать или скрыть окно, открыть настройки либо завершить приложение. Также для выхода можно нажать `Ctrl+Shift+X` или остановить процесс в открытом PowerShell с помощью `Ctrl+C`.

Для клонирования в новый каталог полный набор команд выглядит так:

```powershell
git clone https://github.com/amoorkie/cue-for-windows.git
Set-Location cue-for-windows
npm ci
npm start
```

## Сборка установщика

Закройте запущенный cue, затем выполните:

```powershell
npm run dist:win
```

Команда использует `electron-builder` и текущую конфигурацию NSIS из `package.json`. Основные артефакты создаются в каталоге `dist`:

- `dist\cue-0.1.0-windows-x64.exe` — NSIS-установщик для текущей версии и архитектуры проекта;
- `dist\win-unpacked\cue.exe` — распакованное приложение, которое можно запустить без установки.

Имя установщика содержит значение `version` из `package.json`, поэтому после изменения версии имя файла также изменится. Архитектура по умолчанию соответствует архитектуре среды, в которой выполняется сборка.

Для создания только распакованного приложения можно выполнить:

```powershell
npm run pack
```

## Первый запуск и API-ключи

На первом запуске cue показывает краткое руководство. Открыть его повторно можно кнопкой с логотипом cue. Настройки открываются кнопкой `...` или сочетанием `Ctrl+,`, когда окно cue находится в фокусе.

1. Выберите провайдера ответа: OpenAI, Anthropic, Gemini, NVIDIA или Custom для OpenAI-compatible API.
2. Вставьте API-ключ в соответствующее поле.
3. Проверьте модели Fast и Smart. Smart выключен по умолчанию и использует модель Fast; включённый Smart использует модель Smart.
4. Закройте окно настроек кнопкой Done, чтобы сохранить изменения.

### Пользовательские API endpoints

Для каждого LLM-провайдера можно указать `Base URL`. Пустое поле всегда означает фиксированный официальный адрес. Профиль Custom использует стандартный OpenAI Chat Completions API и подходит для OpenRouter, LM Studio, Ollama, vLLM и корпоративных совместимых gateway.

- Обычно OpenAI-compatible адрес заканчивается на `/v1`, например `http://localhost:11434/v1`.
- Для Anthropic нужен native Anthropic Messages API, а для Gemini — native Gemini generate-content API. Если gateway предоставляет Claude или Gemini через OpenAI-совместимый протокол, используйте профиль Custom.
- У Custom можно независимо отключить Bearer-аутентификацию для LLM и compatible STT маршрута локального сервера без ключей.
- Перед сохранением кастомного адреса нужно явно подтвердить, что вы доверяете этому назначению. После смены URL подтверждение сбрасывается.
- HTTP разрешён только для endpoint на этом компьютере (`localhost`, `127.0.0.0/8`, `::1`); LAN и внешние адреса должны использовать HTTPS.

Маршрут распознавания речи настраивается отдельно. Кастомный LLM endpoint не получает аудио автоматически. Для OpenAI, Gemini или совместимого `/audio/transcriptions` endpoint включите соответствующий STT route, укажите отдельные `STT key`, модель и `STT URL`, затем отдельно подтвердите передачу ключа и аудио этому адресу. При официальных LLM и STT адресах отдельный STT-ключ необязателен; если LLM использует кастомный адрес, cue не переиспользует его ключ для STT без явного ввода в поле `STT key`.

Поддержка распознавания речи устроена отдельно от выбранного провайдера ответа и его LLM endpoint:

- OpenAI может выполнять и запросы к LLM, и распознавание через Whisper, если ключу разрешён audio API;
- Gemini может выполнять и запросы к LLM, и распознавание речи;
- Anthropic и NVIDIA не предоставляют cue распознавание речи, поэтому для прослушивания вместе с их ключом нужно добавить ключ OpenAI или Gemini;
- по умолчанию cue пробует включённые маршруты OpenAI, затем Gemini; явно включённый compatible STT route идёт последним.

Ключи хранятся локально в открытом виде в файле:

```text
%APPDATA%\cue\cue-data.json
```

Не публикуйте этот файл и не добавляйте его в репозиторий. Скриншоты и аудиофрагменты отправляются напрямую выбранным и явно подтверждённым LLM/STT-адресам; собственного сервера и телеметрии у cue нет.

## Управление

- `Ctrl+Enter` — глобальный Assist: анализ текущего экрана и недавнего разговора.
- `Ctrl+H` — глобальное решение задачи программирования с текущего экрана.
- `Ctrl+Shift+T` — показать или скрыть окно cue; то же действие доступно через значок в системном трее.
- `Ctrl+Shift+X` — глобальное завершение cue.
- `Ctrl+,` — открыть Settings, когда cue находится в фокусе.
- `Enter` в поле ввода — отправить вопрос.
- `Shift+Enter` — новая строка в поле ввода.

Кнопка с квадратом в верхней панели включает или выключает прослушивание. Зелёная точка означает активный режим захвата; жёлтая точка и сообщение в панели указывают на ошибку микрофона или системного loopback. Кнопка Hide сворачивает основную панель, а верхнюю панель можно перетаскивать мышью.

В панели отображается живой конспект разговора с раздельными каналами «Вы» и «Собеседник». Распознанный текст хранится в памяти текущего сеанса и используется кнопками «Что сказать?», «Что спросить дальше?», «Итоги» и «Помощь». Повторяющиеся фразы от разных аудиоканалов автоматически отбрасываются.

## Разрешение на микрофон

Если cue не слышит микрофон:

1. Откройте Settings Windows.
2. В Windows 11 перейдите в Privacy & security → Microphone. В Windows 10 — Privacy → Microphone.
3. Включите Microphone access и Let desktop apps access your microphone.
4. Полностью перезапустите cue.

При запуске из исходников доступ может отображаться как доступ Electron или настольного приложения. При запуске установленной сборки ищите cue.

## Диагностика распознавания речи

Распознавание выполняется порциями примерно раз в 2,2 секунды, а тишина и очень короткие фрагменты отбрасываются. Для проверки произнесите фразу длительностью хотя бы одну секунду, подождите несколько секунд, затем нажмите «Что сказать?» или «Итоги».

Если распознавание не работает:

- проверьте, что добавлен OpenAI- или Gemini-ключ;
- для OpenAI убедитесь, что ключу разрешён Whisper/audio API, а не только chat API;
- при ошибке `401` проверьте правильность и срок действия ключа;
- при ошибке `403` разрешите audio API для OpenAI либо добавьте Gemini-ключ;
- после изменения ключей закройте Settings, выключите и снова включите прослушивание; если ошибка сохранилась, перезапустите cue;
- запускайте через `npm start` и смотрите сообщения `[stt]` и `[renderer]` в PowerShell.

## Диагностика системного звука

На Windows cue использует loopback-захват Electron: звук приложений записывается отдельно как канал Them, а микрофон — как канал You.

Если собеседник или звук встречи не распознаётся:

1. До включения прослушивания выберите в Windows нужное устройство вывода по умолчанию.
2. Убедитесь, что звук встречи действительно воспроизводится через это устройство и не отключён в микшере громкости.
3. Выключите и снова включите прослушивание после смены устройства вывода.
4. Перезапустите cue и приложение встречи.
5. Проверьте сообщение в панели cue; при успешном запуске из исходников в PowerShell также появляется `system audio: capturing loopback`.

Некоторые приложения, защищённый медиаконтент, эксклюзивный режим аудиоустройства и нестандартные виртуальные устройства могут не отдавать звук в loopback. Для проверки сначала воспроизведите обычный системный звук, например ролик в браузере.

Если один из каналов не открылся, cue показывает жёлтый индикатор и отдельное сообщение об ошибке. Для полной проверки распознавания всё равно протестируйте каналы You и Them по очереди с настроенным STT-ключом.

## Защита от захвата экрана

cue вызывает Electron `setContentProtection(true)`. На Windows это использует `WDA_EXCLUDEFROMCAPTURE`:

- в Windows 10 2004+ и Windows 11 совместимый механизм захвата должен исключать окно cue из изображения;
- в более старых версиях Windows окно обычно попадает в запись как чёрный прямоугольник.

Это защита по принципу best effort, а не гарантия невидимости. Отдельные программы или режимы захвата могут обходить системный механизм. Защита также не действует на внешнюю камеру, карту захвата и другие способы записи итогового видеосигнала.

Перед важным звонком обязательно сделайте тестовую запись тем же приложением и тем же режимом, которые будут использоваться во время демонстрации. В Zoom, если доступна такая настройка, используйте Advanced capture with window filtering и повторно проверьте результат. Не полагайтесь на cue в ситуациях, где скрытая помощь нарушает правила платформы, экзамена, собеседования или требования к согласию на запись.

Переменная окружения `CUE_NO_PROTECT=1` отключает эту защиту и предназначена только для отладки. Не задавайте её при обычном запуске.

## SmartScreen и неподписанный установщик

Текущая конфигурация не содержит сертификата подписи кода. Собранные `cue.exe` и NSIS-установщик не подписаны, поэтому Windows SmartScreen может показать предупреждение Windows protected your PC или антивирус может потребовать дополнительную проверку.

Если вы сами собрали приложение из проверенных исходников, в окне SmartScreen можно выбрать More info → Run anyway. Не отключайте SmartScreen или антивирус целиком. Перед распространением сборки подпишите исполняемые файлы доверенным Windows code-signing сертификатом и добавьте timestamp; без этого предупреждения будут появляться у других пользователей даже для неизменённой сборки.
